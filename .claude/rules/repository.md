# Repository Rules

- Keep changes scoped and reviewable.
- Do not create duplicate canonical files under alternate capitalization/path spellings.
- Preserve existing CI and evidence workflows unless the change is intentional and verified.
- Prefer existing project conventions over introducing a new framework.
- Do not turn implementation-choice technologies into architecture invariants.
- Use the repository's existing Python packaging, pytest and Ruff configuration unless there is a documented reason to change it.
