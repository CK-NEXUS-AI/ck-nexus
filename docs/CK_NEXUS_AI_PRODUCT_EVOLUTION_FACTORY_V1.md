# CK-NEXUS AI Product Evolution Factory v1

## Objective

Continuously discover valuable problems, preserve knowledge, build candidate solutions, verify them independently, and close only evidence-backed work.

## Operating loop

MARKET / OSS / RESEARCH / FEEDBACK
-> IDEA HARVEST
-> NORMALIZE / DEDUP / PROVENANCE
-> OPPORTUNITY SCORE
-> PRODUCT QUEUE
-> ARCHITECT
-> BUILD / DESIGN / REPAIR
-> TEST / SECURITY / PERFORMANCE
-> INDEPENDENT VERIFICATION
-> EVIDENCE
-> CLOSE or REPAIR
-> KNOWLEDGE CAPITAL
-> NEXT ITERATION

## Product-quality requirement

Technical correctness is necessary but insufficient. Candidate products must also be evaluated for UX, visual quality, onboarding, documentation, market demand, differentiation, time-to-value, and commercial fit.

## Autonomous closure

The factory may execute a task without asking for confirmation when policy and capability leases permit it. It may select alternative methods when the primary path fails. It must stop on authorization, secret, production, budget, or verification boundaries.

### Closure contract

DONE requires:

1. implementation evidence;
2. test evidence;
3. security evidence;
4. independent verification;
5. provenance;
6. no increased regression;
7. no unauthorized production mutation.

A score, model claim, passing local test, or successful build is not sufficient.

## Knowledge preservation

Every experiment records:

- source/provenance;
- method attempted;
- result;
- failure reason;
- evidence;
- reusable lesson;
- affected capability;
- replacement/successor relationship.

Failed work is retained as negative knowledge so the factory does not repeatedly rediscover the same failure.

## Market loop

The factory continuously converts external signals into structured opportunities. An opportunity is not automatically a product decision; it must pass evidence, feasibility, value, and policy gates.

## 24-hour operation

24-hour behavior is implemented as scheduled/event-driven runs, not an unbounded process. Each run has a budget, iteration limit, alternative-path limit, concurrency limit, and evidence artifact. A future agentic controller may activate execution only after its provider capabilities and independent verification path are proven.

## Current boundary

This component is development infrastructure. It does not authorize production deployment, financial transactions, secret acquisition, or autonomous external side effects.
