2. What is GitHub? — cloud platform for repositories, review, projects and collaboration
3. Key concepts — repository, commit, branch, remote, pull request
4. Install Git — platform-specific installation
5. Configure Git — user name/email and `git config --list`
6. Create repository — init, add remote, add/commit
7. Connect to GitHub — SSH key, add key, test connection
8. First commit — `git add`, `git commit`
9. Push to GitHub — `git push -u origin main`
10. Big picture — read/write code → commit → branch → PR → review/merge → deploy

## CK-NEXUS translation

- repository = bounded project boundary
- commit = immutable evidence checkpoint
- branch = isolated work identity
- remote = approved connector target
- pull request = human/policy review gate
- push = controlled publication, not production deployment
- deploy = separate staging/production gate with rollback
- SSH = credentialed transport that must remain outside logs and model context

## Design ideas derived from the image

- Show a visible lifecycle in the Thai control center
- Give every task a timeline with SHA, branch, checks and evidence
- Separate “planned”, “candidate”, “PR open”, “CI green”, “approved”, “staged” and “deployed”
- Provide beginner-friendly command explanations while keeping the actual executor policy-bound
- Make collaboration and history first-class data, not just chat messages
