# CK-NEXUS System Skills Harvest v1

## Goal
Harvest reusable system capabilities from prior CK-NEXUS work and AI collaboration history without importing task-specific user data. Every candidate is deduplicated against canonical CK-NEXUS before development.

## Admission lifecycle
`DISCOVER -> DEDUP -> BENCHMARK -> SECURITY_REVIEW -> INDEPENDENT_VERIFY -> CANONICAL_ADOPT`

Development-only evaluation may proceed automatically for read-only or local-reversible work. Credentials, outbound sends, paid actions, legal acceptance, permission expansion, production changes, merge, deploy, and final verification remain human-gated.

## Wave 0 — Reuse canonical
- Pattern Registry / Pattern Selector
- Connector Fabric
- Provider Router
- Sandboxed Execution
- Observability Fabric
- Council Governance

These must be reused rather than rebuilt.

## Wave 1 — Immediate development evaluation
- Command Normalizer
- Capability Admission Fabric
- Capability Benchmark
- Research Delta Scout
- Cost/Quota Guard
- External Evidence Intake
- Inter-chat Coordination Protocol
- Skill Versioning / Supersession / Rollback

These improve control, reuse, automation reliability, and evidence quality without changing production authority.

## Wave 2 — Typed intelligence infrastructure
- Semantic IR
- Dependency Graph Memory
- Causal/Temporal Memory
- Retrieval Quality Evaluator
- Long-context Budgeter
- Adaptive Scheduler
- Self-healing Supervisor

Each requires a measurable baseline and deterministic regression tests before adoption.

## Wave 3 — Guarded extensions
- Human Gate Manager
- Tool Permission Compiler
- Multimodal Artifact Router
- Stronger provenance replay/fork binding

These may influence permissions or side effects and therefore cannot auto-adopt.

## Quarantine / rebuild-from-verified-base
The following historical lineages remain blocked because current evidence is stale, incomplete, or prior CI failed:
- Failure Memory
- State Projector
- Learning Consolidator
- Durable Execution v3
- AGNES Triad Parallel Scheduler
- AGNES Evidence Evaluator

No historical claim is treated as implementation evidence. A new candidate must pass tests, security review, and independent verification.

## Automatic decision rule
`REUSE` means use existing canonical capability. `EXTEND` means add a bounded development delta. `NEW_SKILL` and `EVALUATE` may only enter development evaluation. `BLOCKED_BY_EVIDENCE` and `REJECT` stop automatically.

`auto_safe=true` means safe to evaluate or reuse in development; it never means permission to merge, deploy, modify production, spend money, expose secrets, or self-approve.

## Q10 isolation
This work is development-only. Frozen Q10 commit/tree, Q10 NOT_VERIFIED, Q11/Q12 BLOCKED, and Production NO-GO are unchanged by this catalog.
